# First Read v0.1 — release draft

**Status:** unpublished release candidate

## What First Read is

First Read is a cooperative suspense instrument for AI companions. It gives a
reader one bounded passage at a time, requires that reader to seal a response
before continuing, and preserves enough reader-authored continuity to survive a
process or context reset without exposing future prose.

The protected object is not merely the ending. It is the companion's changing
relationship to the work: early judgments made without later evidence,
predictions that may fail, ordinary moments whose importance is not yet known,
and the particular revision that becomes possible only after having waited.

In plot-heavy work, this protects surprise. In quieter work, it protects
duration and situated empathy. The reader meets a life while information is
still incomplete instead of receiving every scene pre-labelled by its eventual
function.

## What ships in v0.1

### Protected reading core

- Prose-free `plan` preflight with word count, passage estimate, size range,
  mechanical call estimate, and relative load.
- Structure-aware passage shaping that treats word targets as goalposts and
  yields to headings, paragraphs, and ornamental scene breaks.
- `begin` to create a private session and reveal passage one atomically.
- `step` to seal the current response and reveal the next passage atomically.
- A response gate: the engine cannot advance past an unanswered passage.
- Exact replay of the current passage without exposing the next one.
- Immutable passage responses and versioned append-only checkpoints.
- Cold-process `resume` containing only already-revealed material.
- Honest prior-exposure receipts rather than false claims of pristine reading.
- Fail-closed refusal when malformed formatting would create an oversized
  passage before first exposure.

### Blind public-web ingestion

- Public HTTP(S) article retrieval into opaque, owner-only Markdown and JSON
  files without printing the title, URL, snippet, or prose.
- Rejection of embedded credentials and private, loopback, link-local, or
  reserved network targets, including redirect revalidation.
- Response-size and content-type limits, atomic writes, and an intentionally
  coarse article-versus-stub quality receipt.
- Structured Trafilatura extraction that preserves paragraphs, headings,
  quotes, lists, and explicit line breaks.
- Honest refusal when a publisher blocks unauthenticated retrieval or the
  extracted result looks like a paywall/stub.

### Human operating guide

- Full versus Lean Context as an independent choice from passage pace.
- Shared versus Solo company and passage/chapter/work scope.
- Flow, Close, Microscopic, Long Flow, and Chapter Lite recommendations.
- Salience and integration practices that keep the journal as evidence of the
  encounter rather than forcing it into the human conversation.
- [First Watch](../FIRST-WATCH.md), a manual shared-screen profile with blind
  rendezvous decisions, intake exposure receipts, pause/resume instructions,
  and disposable synthetic rehearsal dialogue. This is documentation over the
  existing core, not a subtitle importer or automated viewing runner.

## Ecological validation

The release candidate completed a blind read of a public 5,000-word short story
from URL through final discussion:

1. The ingester stored the source without revealing its title or prose.
2. Safe preflight metadata was sufficient for the companion to choose Full
   Context, Solo company, whole-story scope, and adaptive Flow.
3. The companion read 17 protected literary passages and sealed a response
   after each before seeing the next.
4. After completion, it performed a salience pass and a whole-story integration
   reread beside the temporal journal.

The live run also found a genuine extraction defect: a twelve-word publisher
support prompt survived after the literary ending as an eighteenth passage. A
narrow trailing-boilerplate filter and regression were added. A fresh blind
ingest ended on the story itself at 5,000 words across 17 passages ranging from
254 to 339 words.

This matters because the test did more than confirm that commands execute. It
exercised the intended joyflow, preserved prediction and revision, produced a
useful reader-to-reader conversation, and made the product better through a
failure that synthetic prose had not exposed.

A fresh local Git clone and empty Python 3.14.4 virtual environment on Linux
passed all 22 tests without third-party packages. Installing the pinned optional
requirements then succeeded, and the actual Trafilatura adapter extracted a
synthetic HTML article. The README's two-passage Detective Turnip lifecycle
passed planning, first reveal, seal-without-advance, checkpoint, cold-process

The README now uses portable environment paths and explains direct-script

## Known limits

v0.1 is a protected-reading **engine and operating method**, not yet an
autonomous model runner. Full Context, Lean Context, Shared, and Solo describe
how a companion or harness operates the engine; the CLI does not invoke a model.

The following remain post-v0.1 work:

- formal book/chapter/section hierarchy;
- a hard scope-close action that seals chapter one without revealing chapter
  two;
- first-class chapter salience cards and rolling book state;
- measured Lean-versus-Full token accounting;
- automatic exact-final-sentence markers for Shared reading;
- browser-saved HTML, PDF, authenticated-page, and paywalled-page import;
- MCP packaging, a graphical interface, and adversarial containment.

First Read controls its own disclosures. It cannot prevent a companion with
filesystem access from deliberately opening the source or database.

## Next proof

The next ecological milestone is not another short story. It is a disposable
multi-chapter work with explicit authored headings:

1. Import the whole work without prose exposure.
2. Read chapter one through several protected passages.
3. Seal the final chapter-one response and stop before any chapter-two prose.
4. Create a chapter salience card and rolling-state delta from revealed
   material only.
5. Resume in a fresh process and prove that the safe packet cannot cross the
   chapter boundary.

Only after that mechanical proof should an irreplaceable novel be trusted to
the long-work joyflow.

## Release posture

This document is a draft for private review. It is not a tag, published release,
or claim that the book-scale design is complete. The v0.1 label belongs to the
working short-form core; the next version begins when chapter scope becomes a
first-class enforced boundary.
